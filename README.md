# SMGC

**SMGC** — компоненты графики на OpenGL для ядра [SMPB](https://github.com/s1m-ila/SMPB). Их два:

- **`SMGC`** (3D) открывает окно, принимает от других компонентов сцену в виде списка SDF-объектов (шары, кубы, капсулы, фракталы) и рисует её **гибридным** способом: полигональные прокси-меши отсекают пустое пространство, а на их поверхности запускается ray-marching, который и даёт итоговую картинку.
- **`SMGC2D`** (2D) рисует плоские фигуры с неподвижной камерой: прямоугольники, треугольники, круги, эллипсы, скруглённые прямоугольники, кольца и отрезки. Фигуры задаются задачами вида «нарисовать круг с таким центром и радиусом» в пиксельных координатах окна. Вся геометрия — полигоны, а скруглённые фигуры вырезаются из квадов фрагментным шейдером. Ещё он выводит текст в UTF-8 (латиница и кириллица) шрифтом TTF.

## Возможности

- Готовый компонент `SMGC` для ядра SMPB: окно GLFW, контекст OpenGL 4.4 core, загрузка функций через glad.
- Сцена передаётся задачами SMPB: очистить, добавить объект, показать. Объекты хранятся с **двойной буферизацией**, поэтому сцену можно собирать по частям, пока на экране остаётся предыдущая.
- Примитивы: шар, куб, капсула. Фракталы: Mandelbulb и губка Менгера.
- Гибридный рендеринг в 3 прохода: depth-prepass по прокси-мешам, ray-marching только в ближайшей к камере прокси-поверхности, оранжевый каркас поверх. Каркас можно выключить задачей.
- Атрибуты вершин для каждого объекта: `polygonal` рисует объект обычными полигонами с плоским затенением вместо ray-marching, `attached` привязывает объект к камере.
- Прокси-меши строятся на CPU и гарантированно **охватывают** свои SDF, поэтому луч можно начинать прямо с их поверхности.
- Отсечение по дальности: дальние объекты не попадают ни в геометрию, ни в SSBO, а у пограничных удаляются дальние треугольники.
- Освещение: точечный источник, мягкие тени (отключаются задачей), ambient occlusion по числу шагов, туман и дизеринг.
- Бесконечный пол в клетку, который всегда следует за камерой.
- Камера и дальность прорисовки задаются задачами.
- Подписка на клавиши: SMGC каждый тик сообщает подписчикам, нажаты ли их клавиши. Свободной камерой в примере управляет компонент `Scene3D`.
- 2D-компонент `SMGC2D`: 7 базовых фигур, координаты в пикселях от левого верхнего угла, прозрачность через альфа-канал, сглаженные края у скруглённых фигур. Каркас и подписка на клавиши работают так же, как в 3D.
- Текст: строка UTF-8 с латиницей, кириллицей и типографскими знаками, любой размер, перенос строк через `\n`, выравнивание влево, по центру или вправо. Глифы хранятся в SDF-атласе, поэтому текст остаётся чётким и на 12, и на 100 пикселях. Шрифт по умолчанию — DejaVu Sans, его можно сменить задачей. В `SMGC2D` текст рисуется вместе с фигурами, в `SMGC` — поверх 3D-сцены как HUD.
- Косинусные палитры `PaletteCosinka` / `PaletteCosinka2` для красивых цветов.
- Собирается как статические библиотеки `smgc::display3D` и `smgc::display2D` с общей частью `smgc::common` и подключается к другим CMake-проектам через `add_subdirectory` или `FetchContent`.
- В примере 3D- или 2D-сцена выбирается одним дефайном `SMGC_EXAMPLE_DIMENSION`.

## Сборка

### Требования

- CMake 3.21 или новее
- Компилятор с поддержкой C++23 (проверено на GCC)
- Ninja или Make
- GLFW 3, GLM и OpenGL (GLVND), установленные в системе: они ищутся через `find_package`
- Видеокарта и драйвер с поддержкой GLSL 4.60: шейдеры начинаются с `#version 460 core`

glad лежит в `third_party/glad` и собирается вместе с проектом, растеризатор шрифтов stb_truetype — в `third_party/stb`. smpb скачивается автоматически (см. ниже).

Все зависимости описаны в `shell.nix`, поэтому на NixOS или с установленным Nix достаточно зайти в окружение:

```bash
nix-shell
```

### Обычная сборка

```bash
cmake -S . -B build -G Ninja
cmake --build build
```

Собираются цели:

| Цель | Тип | Результат | Описание |
|------|-----|-----------|----------|
| `smgc_common` (псевдоним `smgc::common`) | статическая библиотека | `libsmgc_common.a` | Общая часть обоих рендереров: `Shader`, `VAO`, `VBO`, `EBO`, `ObjectsBuffer`, палитры, задачи `taskDefinitions.h` и `taskDefinitions2D.h`, генератор фигур `Shapes2D`, шрифт `Font` (stb_truetype собирается внутри него) и 2D-слой `Layer2D`. Публичные заголовки лежат в `include/smgc/`. smpb, glad, GLFW и GLM подключены как `PUBLIC`-зависимости, поэтому их заголовки и требование C++23 передаются всем, кто линкуется с библиотекой. |
| `smgc_display3D` (псевдоним `smgc::display3D`) | статическая библиотека | `libsmgc_display3D.a` | 3D-компонент `SMGC` и генератор прокси-мешей `ObjectsGenerator`. Текст поверх сцены `SMGC` рисует через `Layer2D` из общей части. Подключается как `<smgc/display3D.h>`. Линкуется с `smgc::common` как `PUBLIC`. |
| `smgc_display2D` (псевдоним `smgc::display2D`) | статическая библиотека | `libsmgc_display2D.a` | 2D-компонент `SMGC2D`. Подключается как `<smgc/display2D.h>`. Линкуется с `smgc::common` как `PUBLIC`. |
| `glad` | статическая библиотека | `libglad.a` | Загрузчик функций OpenGL из `third_party/glad`. Создаётся, только если цели `glad` ещё нет. |
| `smpb_core` (псевдоним `smpb::core`) | статическая библиотека | `libsmpb_core.a` | Ядро SMPB. Скачивается через `FetchContent` из [github.com/s1m-ila/SMPB](https://github.com/s1m-ila/SMPB), только если цели `smpb::core` ещё нет. |
| `smgc` | программа | `smgc`, `files/default.vert`, `files/default.frag`, `files/display2D.vert`, `files/display2D.frag`, `files/DejaVuSans.ttf`, `files/core.config` | Пример из `example/`, слинкованный с `smgc::display3D` и `smgc::display2D`. Какая сцена запустится, задаёт `SMGC_EXAMPLE_DIMENSION` в `example/main.cpp` (см. [Запуск](#запуск)). Собирается, только если включена опция `SMGC_BUILD_EXAMPLE`. После сборки шейдеры, шрифт и `core.config` копируются из `files/` репозитория в папку `files/` рядом с программой. |

Если `CMAKE_BUILD_TYPE` не задан, по умолчанию используется `Release`. В `Release` включается межмодульная оптимизация (LTO), если компилятор её поддерживает. Тип сборки и LTO настраиваются только тогда, когда smgc собирается как самостоятельный проект. Внутри другого проекта эти настройки берутся из него.

| Опция | По умолчанию | Описание |
|-------|--------------|----------|
| `SMGC_BUILD_EXAMPLE` | `ON`, если smgc собирается сам; `OFF` внутри другого проекта | Собирать ли программу `smgc` |

Сборка только библиотеки:

```bash
cmake -S . -B build -G Ninja -DSMGC_BUILD_EXAMPLE=OFF
cmake --build build
```

Отладочная сборка:

```bash
cmake -S . -B build-debug -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build-debug
```

Для сборки через Make флаг `-G Ninja` не указывается, а в папке сборки запускается `make`.

Установка программы `smgc` в `bin/` выбранного префикса:

```bash
cmake --install build --prefix /путь/установки
```

Устанавливается только программа: библиотека, заголовки, шейдеры и `core.config` не устанавливаются.

В папке сборки генерируется `compile_commands.json` для clangd.

## Подключение к другому проекту

smgc подключается как CMake-подпроект. В этом случае собираются только библиотеки: программа `smgc` не собирается, а тип сборки и LTO не меняются. GLFW, GLM и OpenGL по-прежнему должны быть установлены в системе.

### Через `add_subdirectory`

Если исходники smgc лежат рядом с проектом или внутри него:

```cmake
cmake_minimum_required(VERSION 3.21)
project(myapp LANGUAGES C CXX)

add_subdirectory(../smgc smgc)

add_executable(myapp main.cpp)
target_link_libraries(myapp PRIVATE smgc::display3D)
smgc_copy_files(myapp)
```

Второй аргумент `add_subdirectory` (папка сборки) обязателен, если путь к smgc лежит вне папки проекта.

Для 2D вместо `smgc::display3D` линкуется `smgc::display2D`. Можно слинковать обе библиотеки: классы и имена компонентов у них разные (`SMGC` и `SMGC2D`), поэтому они не конфликтуют.

### Через `FetchContent`

smgc скачивается из репозитория при конфигурации проекта:

```cmake
cmake_minimum_required(VERSION 3.21)
project(myapp LANGUAGES C CXX)

include(FetchContent)
FetchContent_Declare(smgc
  GIT_REPOSITORY https://github.com/s1m-ila/SMGC.git
  GIT_TAG        main
)
FetchContent_MakeAvailable(smgc)

add_executable(myapp main.cpp)
target_link_libraries(myapp PRIVATE smgc::display3D)
smgc_copy_files(myapp)
```

### Функция `smgc_copy_files`

`smgc_copy_files(<цель>)` добавляет к цели шаг `POST_BUILD`, который копирует `default.vert`, `default.frag`, `display2D.vert`, `display2D.frag` и `DejaVuSans.ttf` из `files/` репозитория smgc в папку `files/` рядом с собранной программой. Без этих файлов компоненты `SMGC` и `SMGC2D` не запустятся: оба загружают 2D-шейдеры и шрифт для текста. `core.config` эта функция не копирует: о нём заботится сам проект.

### Своя версия smpb или glad

smgc скачивает smpb, только если цели `smpb::core` ещё нет, и собирает свой glad, только если нет цели `glad`. Чтобы использовать свою копию, её нужно подключить **до** smgc:

```cmake
add_subdirectory(../smpb smpb)
add_subdirectory(../smgc smgc)
```

В обоих случаях заголовки подключаются с префиксом `smgc/`. Главный заголовок каждого рендерера подтягивает всё, что нужно для работы с ним:

```cpp
#include <smgc/display3D.h>
#include <smgc/display2D.h>
```

## Запуск

```bash
cd build
./smgc
```

Какая сцена запустится, задаёт дефайн в начале `example/main.cpp`:

```cpp
#define SMGC_EXAMPLE_DIMENSION 2
```

| Значение | Компоненты | Окно |
|----------|------------|------|
| `2` (по умолчанию) | `Config` → `SMGC2D` → `Scene2D` | `SMGC2D` |
| любое другое, например `3` | `Config` → `SMGC` → `Scene3D` | `SMGC` |

Обе сцены компилируются всегда, после смены значения нужно пересобрать программу.

Шейдеры 3D читаются из `files/default.vert` и `files/default.frag`, шейдеры 2D — из `files/display2D.vert` и `files/display2D.frag`, шрифт — из `files/DejaVuSans.ttf`, а конфигурация smpb — из `files/core.config`. Все пути отсчитываются от **текущей рабочей папки**, поэтому программа запускается из папки сборки. Файлы копируются туда командой `copy_if_different` при сборке программы `smgc`. Если изменился только шейдер в `files/` репозитория, копия в папке сборки остаётся старой до следующей пересборки `smgc`, а сам шейдер подхватывается только после перезапуска.

Открывается окно `SMGC` или `SMGC2D` размером 800×800, его можно растягивать. При старте в лог выводятся версия OpenGL и полный текст обоих шейдеров. Программа работает, пока окно не закроют: тогда компонент рендера вызывает `Core_stop()`. Остановить её можно и через `Ctrl+C` или `SIGTERM`, это обрабатывает ядро smpb.

Кадр рисуется один раз за тик ядра, поэтому частота кадров совпадает с TPS из `core.config`.

## Управление в примере

### 3D: камера (`Scene3D`)

Камерой управляет компонент `Scene3D` из примера. Он подписывается на клавиши, по их состоянию двигает свою камеру и каждый тик отправляет её в `SMGC` (см. [Подписка на клавиши](#подписка-на-клавиши)).

| Клавиша | Действие |
|---------|----------|
| `←` / `→` | Поворот влево / вправо (yaw) |
| `↑` / `↓` | Наклон вверх / вниз (pitch), ограничен диапазоном ±89° |
| `W` / `S` | Движение вперёд / назад по направлению взгляда, с учётом наклона |
| `A` / `D` | Движение влево / вправо в горизонтальной плоскости |
| `Q` / `E` | Уменьшить / увеличить скорость движения и поворота в 2 раза. Срабатывает не чаще одного раза за 10 тиков |
| `C` | Округлить углы до 45°, а позицию до центра ближайшей клетки (`floor(x) + 0.5`) |
| `R` | Сбросить позицию, углы и скорости |

Скорость по умолчанию: 3 единицы в секунду и 90° в секунду. Шаг считается как `скорость / TPS`, поэтому скорость камеры не зависит от TPS. Камера стартует в начале координат и смотрит вдоль оси +Z, пол находится на высоте y = −1.

В режиме отладки ядра на каждом тике в лог выводятся `camera.pos` и `camera.rot`. В левом верхнем углу окна `Scene3D` выводит текстом позицию и углы камеры и текущую скорость.

### 2D: игрок (`Scene2D`)

`Scene2D` каждый тик рисует все 2D-фигуры с анимированными размерами и цветами, полупрозрачный прямоугольник поверх круга и белый круг-«игрок» с кольцом вокруг. Игрок рисуется последним, поэтому он всегда сверху. Текстом выводятся заголовок, подписи под фигурами (по центру), подсказка по клавишам (вправо, 3 строки), номер тика и позиция игрока (влево) и пульсирующее «Привет!».

| Клавиша | Действие |
|---------|----------|
| `W` / `S` | Движение игрока вверх / вниз |
| `A` / `D` | Движение игрока влево / вправо |
| `O` | Включить / выключить оранжевый каркас. Срабатывает один раз на нажатие |
| `R` | Вернуть игрока в стартовую точку (400, 700) |

Скорость игрока — 300 пикселей в секунду, шаг считается как `скорость / TPS`. Позиция игрока не ограничена окном.

## Файл конфигурации `core.config`

Файл читает компонент `Config` из smpb, формат и список команд описаны в [README smpb](https://github.com/s1m-ila/SMPB#файл-конфигурации-coreconfig). Сам smgc из конфигурации ничего не читает, но от `SET_TPS` зависит частота кадров и скорость анимации в примере.

`files/core.config` в репозитории:

```
SET_TPS 30
SET_TPS BABAX
SET_DEBUGMODEENABLED TRUE
LOAD_DLL Base/Userlib.dll
```

Вторая строка с некорректным значением оставлена как пример: `Config` выведет для неё `no valid value!`. Режим отладки в примере включается в `example/main.cpp` вызовом `core.setDebugModeEnabled(true)`.

## Архитектура

```
                 ┌──────────────────────────────┐
                 │          Core (smpb)         │
                 │   цикл тиков, TPS, задачи    │
                 └──┬───────────┬───────────┬───┘
       init/tick/death          │           │
                    ▼           ▼           ▼
            ┌──────────┐  ┌──────────┐  ┌──────────┐
            │  Config  │  │   SMGC   │  │ Scene3D  │
            │          │  │  окно,   │  │ (пример) │
            │          │  │ рендер   │  │          │
            └──────────┘  └──┬───▲───┘  └──┬───▲───┘
                             │   │         │   │
                             │   └─────────┘   │   Subscribe, SetCamera,
                             │                 │   Clear → Push × N → Swap
                             └─────────────────┘   KeyState каждый тик
```

`example/main.cpp` добавляет в ядро три компонента по порядку: `Config`, `SMGC` и `Scene3D`. На каждом тике `SMGC` рассылает подписчикам состояние клавиш и рисует кадр. Затем `Scene3D` по нажатым клавишам двигает камеру и отправляет в `SMGC` камеру и новую сцену. Поэтому кадр, нарисованный на тике N, показывает камеру и сцену, отправленные на тике N − 1.

2D-пример устроен так же: вместо `SMGC` стоит `SMGC2D`, вместо `Scene3D` — `Scene2D`, а вместо камеры и объектов отправляются задачи фигур (см. [2D-рендерер SMGC2D](#2d-рендерер-smgc2d)).

### Протокол задач

Компоненты не вызывают методы `SMGC` напрямую, а отправляют ему задачи по имени `"SMGC"`:

| Задача | `taskIdx` | Данные | Что делает |
|--------|-----------|--------|------------|
| `task_SmgcClearObjects` | `1` | — | Очищает буфер B и кладёт в него служебную геометрию: `AntiCube` вокруг камеры и прокси пола |
| `task_SmgcPushObject` | `2` | `std::unique_ptr<Object> obj`, `VertexAttributes attributes` | Добавляет объект в буфер B: строит его прокси-меш с [атрибутами вершин](#атрибуты-вершин) и кладёт сам объект в список для SSBO. Атрибуты необязательны, по умолчанию оба `false` |
| `task_SmgcSwapObjects` | `0` | — | Меняет буферы A и B местами и загружает геометрию A в VBO/EBO |
| `task_SmgcSetOutline` | `3` | `bool enabled` | Включает или выключает оранжевый каркас. По умолчанию включён |
| `task_SmgcSetShadows` | `9` | `bool enabled` | Включает или выключает тени. По умолчанию включены |
| `task_SmgcSetMaxDist` | `4` | `float maxDist` | Задаёт дальность прорисовки. Значение должно быть конечным и больше 0, иначе возвращается `-EINVAL` |
| `task_SmgcSetCamera` | `5` | `Camera camera` | Задаёт позицию и углы камеры |
| `task_SmgcDrawText` | `18` | `std::string text`, `glm::vec2 pos`, `float size`, `glm::vec4 color`, `TextAlign align` | Добавляет текст в HUD поверх сцены (см. [Текст](#текст)) |
| `task_SmgcSetFont` | `19` | `std::string path` | Загружает другой шрифт TTF для HUD |
| `task_SmgcSubscribeKey` | `6` | `int key` | Подписывает отправителя на клавишу |
| `task_SmgcUnsubscribeKey` | `7` | `int key` | Отписывает отправителя от клавиши |

В обратную сторону `SMGC` отправляет подписчикам одну задачу:

| Задача | `taskIdx` | Данные | Когда приходит |
|--------|-----------|--------|----------------|
| `task_SmgcKeyState` | `8` | `int key`, `bool pressed` | Каждый тик, на каждую подписку |

Типичный кадр сцены:

```cpp
sendTask(std::make_unique<task_SmgcSetCamera>(camera), "SMGC");
sendTask(std::make_unique<task_SmgcClearObjects>(), "SMGC");
sendTask(std::make_unique<task_SmgcPushObject>(std::make_unique<Object>(...)), "SMGC");
sendTask(std::make_unique<task_SmgcPushObject>(std::make_unique<Object>(...), VertexAttributes{.polygonal = true}), "SMGC");
// ... остальные объекты
sendTask(std::make_unique<task_SmgcSwapObjects>(), "SMGC");
```

Буфер A всегда показывается на экране, а буфер B собирается. Пока не пришёл `Swap`, на экране остаётся предыдущая сцена, поэтому сцену можно обновлять реже, чем раз в тик. Камеру лучше задавать до `Clear`: `clearObjects` ставит пол под камерой, а `pushObject` отсекает объекты по её позиции. Новая дальность прорисовки тоже начинает действовать со следующего `Clear`. Задачи с неизвестным `taskIdx` молча игнорируются.

### Подписка на клавиши

- Компонент отправляет в `SMGC` задачу `task_SmgcSubscribeKey` с кодом клавиши GLFW (`GLFW_KEY_*`). `SMGC` запоминает пару «id отправителя, клавиша». Допустимы коды от `GLFW_KEY_SPACE` до `GLFW_KEY_LAST`, для остальных возвращается `-EINVAL`. Повторная подписка на ту же клавишу ничего не меняет.
- Каждый тик перед отрисовкой `SMGC` отправляет каждому подписчику `task_SmgcKeyState` на каждую его клавишу. Задача адресуется по id компонента через `sendTask(task, int workerIdx)` из smpb. Состояние берётся из `glfwGetKey` после последнего `glfwPollEvents`.
- Подписчик **обязан** отозвать все подписки в `death()` задачей `task_SmgcUnsubscribeKey`. id компонента в smpb — это номер слота, и после удаления компонента его слот может занять новый компонент. Неотозванная подписка начнёт слать задачи ему.
- Отписка от клавиши, на которую не было подписки, ничего не делает. В `death()` самого `SMGC` все подписки сбрасываются.
- При остановке ядро smpb завершает компоненты в обратном порядке, поэтому `Scene3D`, добавленный после `SMGC`, успевает отписаться, пока `SMGC` ещё работает.
- `SMGC2D` поддерживает те же задачи подписки и работает по тем же правилам.

### Атрибуты вершин

Вторым аргументом `task_SmgcPushObject` принимает `VertexAttributes`. Атрибуты записываются во все вершины прокси-меша объекта, а флаги дублируются в `GpuObject` для шейдера.

| Поле | По умолчанию | Что делает |
|------|--------------|------------|
| `polygonal` | `false` | Объект рисуется своим прокси-мешем с плоским затенением, без ray-marching (см. [полигональные объекты](#гибридный-рендеринг)). В `map` такой объект пропускается: он не виден лучам других объектов и не отбрасывает тени |
| `attached` | `false` | Объект привязан к камере: `data1.yzw` и поворот `data4` задаются в системе камеры (x — вправо, y — вверх, z — вперёд). Объект двигается и поворачивается вместе с камерой, например для HUD или оружия в руке |

Для `attached` объектов:

- вершины прокси-меша получают `attached = 1` и обрабатываются вертексным шейдером как `AntiCube`;
- отсечение по дальности считается от начала координат системы камеры, то есть по расстоянию до камеры;
- в SSBO объект попадает в мировых координатах: перед загрузкой `draw()` переводит его через `AttachedToWorld` по текущей камере. Поэтому цикл `map` не делает лишней работы, а ray-marching и тени работают для таких объектов как для обычных.

### Формат объекта `Object`

`Object` — 4 × `glm::vec4`, 64 байта. В таком виде объект отправляют в `SMGC` задачей `task_SmgcPushObject`. Краткое описание полей лежит в `files/разметка.txt`.

В шейдер уходит не сам `Object`, а `GpuObject`: `pushObject` переводит объект функцией `ToGpuObject`. Матрица поворота считается один раз на CPU, поэтому шейдеру не нужно считать синусы и косинусы в каждом вызове `map`.

| Поле `GpuObject` | Тип | Откуда |
|------------------|-----|--------|
| `data1`, `data2`, `data3` | `glm::vec4` | Копируются из `Object` |
| `invRot[3]` | `glm::vec4` × 3 | Столбцы матрицы мир → объект `transpose(Rx · Ry · Rz)`. В `w` лежат флаги: `invRot[0].w` — `polygonal`, `invRot[1].w` — `attached`, `invRot[2].w = 0` |

`GpuObject` занимает 96 байт с раскладкой std430. В `default.frag` ему соответствует структура `Object` с полем `vec4 invRot[3]`: шейдер собирает из `.xyz` матрицу `mat3`, а `.w` читает как флаги. Обе структуры должны совпадать.

| Поле | `.x` | `.y` | `.z` | `.w` |
|------|------|------|------|------|
| `data1` | тип объекта | позиция x | позиция y | позиция z |
| `data2` | радиус / половина ребра | — | — | длина (капсула) |
| `data3` | R | G | B | A |
| `data4` | поворот вокруг X | поворот вокруг Y | поворот вокруг Z | — |

- Тип хранится как `float` и округляется до целого.
- Поворот задаётся в **радианах** как `Rx · Ry · Rz`. Генератор геометрии поворачивает меш этой матрицей, а шейдер переводит точку в систему объекта транспонированной матрицей `invRot`.
- Цвет берётся из `data3.rgb`, альфа-канал пока не используется.

| Тип | Объект | Параметры | Прокси-меш |
|-----|--------|-----------|------------|
| `1` | Шар | `data2.x` — радиус | UV-сфера, раздутая так, что грани касаются шара |
| `2` | Куб | `data2.x` — половина ребра | Куб того же размера |
| `3` | Капсула | `data2.x` — радиус, `data2.w` — длина | Раздутая UV-капсула |
| `-1` | Mandelbulb (степень 8) | `data2.x` — радиус | Сфера радиусом 1.05 · r — граница фрактала |
| `-2` | Губка Менгера (5 итераций) | `data2.x` — половина ребра | Куб того же размера |

Капсула вытянута вдоль локальной оси Y: это отрезок длиной `length` с центром в точке y = `length − radius`, скруглённый радиусом `radius`.

Отрицательный тип означает фрактальную версию фигуры. В тенях фракталы заменяются своими простыми фигурами, а сами фракталы тени на себе не получают. У капсулы фрактальной версии нет, поэтому тип `-3` на экране не виден: для него строится прокси-меш, но шейдер его не рисует и учитывает только в тенях как обычную капсулу. Объекты других типов не получают прокси-меша и тоже не рисуются.

### Гибридный рендеринг

Полный ray-marching на весь экран дорогой: каждый пиксель идёт от камеры до объекта по шагам. SMGC сокращает путь луча с помощью полигональных прокси-мешей, которые охватывают свои SDF-объекты.

`draw()` рисует один и тот же набор треугольников в 3 прохода:

1. **Depth-prepass.** Запись цвета выключена, `iOutline = 1`, поэтому фрагментный шейдер сразу выходит. В буфере глубины остаётся ближайшая прокси-поверхность.
2. **Ray-marching.** `glDepthFunc(GL_EQUAL)`, запись глубины выключена. В `default.frag` стоит `layout(early_fragment_tests)`, поэтому дорогой шейдер выполняется ровно один раз на пиксель — только для ближайшей прокси-поверхности. Луч стартует прямо с неё: `rd = normalize(fragPos)`, `t0 = length(fragPos)`.
3. **Каркас.** `glDepthFunc(GL_LESS)`, режим `GL_LINE`, `iOutline = 1`: поверх рисуются оранжевые рёбра прокси-мешей. Проход выполняется, только если каркас включён (`task_SmgcSetOutline`).

Чтобы глубина в разных проходах совпадала бит в бит, `gl_Position` в вертексном шейдере объявлен `invariant`.

Старт луча с прокси-поверхности корректен, только если прокси **целиком охватывает** свой SDF: иначе луч начнётся внутри объекта или проскочит его. Поэтому:

- сферы и капсулы строятся функцией `RoundMesh`, которая раздувает меш на вычисленный коэффициент: грани касаются настоящей поверхности, а не режут её;
- для Mandelbulb берётся сфера радиусом 1.05 · r, внутри которой лежит фрактал;
- пол — это тонкий бокс на высоте y = −1 толщиной 2 · `epsilon`, который охватывает шейдерный слой `|y + 1| ≤ 0.5 · EPSILON`. `SMGC::epsilon` — единственный источник этого значения: он передаётся в шейдер как `iEpsilon`, а там `#define EPSILON iEpsilon`;
- вокруг камеры стоит `AntiCube` — куб с половиной ребра `maxDist`, видимый изнутри. Он привязан к камере и по позиции, и по повороту: его вершины задаются прямо в системе камеры, поэтому углы куба всегда лежат на view z = ±`maxDist`. Если бы куб был выровнен по миру, при повороте ровно на ±45° один из углов попадал бы в плоскость камеры (w = 0), и отсечение по ближней плоскости теряло бы треугольник грани. Пиксели, где ближайшей оказалась его поверхность, начинают луч дальше `iMaxDist` и сразу получают цвет тумана.

**Отсечение по дальности.** `pushObject` считает радиус описанной сферы объекта (`ObjectBoundingRadius`) и расстояние от её центра до камеры:

- если сфера целиком дальше `maxDist`, объект не попадает ни в геометрию, ни в SSBO;
- если сфера пересекает границу, `CullFarTriangles` удаляет треугольники, у которых все 3 вершины дальше `maxDist`, и вершины, оставшиеся без треугольников;
- объекты неизвестных типов не отсекаются никогда, `AntiCube` тоже;
- у `attached` объектов расстояние считается от камеры в её системе координат.

**Полигональные объекты.** У вершин объекта с атрибутом `polygonal` стоит `polygonal = 1`. Проходы остаются те же, но во втором проходе фрагментный шейдер для таких пикселей не запускает луч, а сразу закрашивает прокси-поверхность:

- нормаль грани считается через `cross(dFdx(fragPos), dFdy(fragPos))` и разворачивается к камере, поэтому затенение плоское и каждая грань видна;
- базовый цвет берётся из `data3.rgb` объекта в SSBO. Чтобы его найти, каждая вершина хранит `objectIdx` — номер объекта в `Objects_B`, который проставляет `pushObject`;
- пол и `AntiCube` всегда рисуются ray-marching. Если их вершинам поставить `polygonal = 1`, пол (`objectIdx = -1`) закрасится той же плиткой, а `AntiCube` (`objectIdx = -2`) получит цвет тумана;
- освещение — half-Lambert от того же точечного источника (2, 4, 2), без теней и ambient occlusion;
- туман и дизеринг такие же, как в ray-marching;
- в `map` полигональный объект пропускается по флагу `invRot[0].w`. Ray-marching других объектов и тени его не видят.

Объекты рисуются в форме своих прокси-мешей: шары и капсулы немного раздуты, фракталы выглядят как сфера или куб, а тип `-3` виден как обычная капсула.

**Порядок обхода вершин.** Проекция левосторонняя, поэтому у видимого треугольника `cross(b - a, c - a)` по правилу правой руки смотрит **внутрь** фигуры. Включено отсечение задних граней (`GL_BACK`, `GL_CCW`).

### Шейдеры

`files/default.vert` строит проекцию вручную, без матрицы MVP:

- мировые вершины (`attached = 0`) переводятся в систему камеры как `R · (aPos - iCameraPos)`. Вершины с `attached = 1` уже заданы в системе камеры: `viewPos = aPos`, они двигаются и поворачиваются вместе с камерой. В `fragPos` для них уходит `transpose(R) · aPos` — направление в мировых осях, чтобы луч ray-marching шёл правильно;
- `aObjectIdx` и `aPolygonal` передаются во фрагментный шейдер без интерполяции (`flat`) как `fragObjectIdx` и `fragPolygonal`;
- поворот камеры собирается из углов `iCameraRot` в градусах как `Rz · Rx · Ry`;
- `w = z` в системе камеры, ближняя и дальняя плоскости — 0.01 и 1000;
- поле зрения по меньшей стороне окна — около 53°, при растягивании окна картинка не искажается.

`files/default.frag` — ray-marcher, который стартует с прокси-поверхности:

| Параметр | Значение |
|----------|----------|
| `ITERATIONS` | 1000 шагов луча |
| `iMaxDist` | Дальность прорисовки, то есть `SMGC::maxDist` (по умолчанию 50) |
| `EPSILON` | `iEpsilon`, то есть `SMGC::epsilon` = 0.0005 |
| Свет | Точечный источник в (2, 4, 2), half-Lambert |
| Тени | Мягкие, 40 шагов, `k = 16`, затемняют не больше чем в 2 раза. Считаются, только если `iShadows = 1` |
| Ambient occlusion | По числу шагов, которые понадобились лучу |
| Туман | Квадратичный, к серому 0.28 на `iMaxDist` |
| Пол | Плоскость y = −1, плитка 1×1 с тёмными швами |

Uniform-переменные, которые `SMGC` задаёт каждый кадр:

| Uniform | Тип | Значение |
|---------|-----|----------|
| `iTime` | `float` | Время в секундах: `tickCounter / TPS` |
| `iResolution` | `vec2` | Размер окна в пикселях |
| `iCameraPos` | `vec3` | Позиция камеры |
| `iCameraRot` | `vec3` | Углы камеры в градусах: pitch, yaw, roll |
| `iMaxDist` | `float` | `SMGC::maxDist`: дальность луча и тумана |
| `iEpsilon` | `float` | `SMGC::epsilon` |
| `iOutline` | `float` | `1` — быстрый выход с оранжевым цветом (prepass и каркас), `0` — ray-marching |
| `iShadows` | `float` | `1` — тени включены, `0` — выключены |

Объекты передаются через SSBO `ObjectsBuffer` с `binding = 0`, массив `ObjectsData.items[]` из `GpuObject`. В `map` точка переводится в систему объекта одним умножением: `obj.invRot * (p - obj.data1.yzw)`.

`files/default copy.frag` — старый полноэкранный ray-marcher, он оставлен для сравнения и не загружается. Если меняется SDF в шейдере, нужно поменять и его прокси в `ObjectsGenerator` (`GenerateObject` и `ObjectBoundingRadius`).

### 2D-рендерер SMGC2D

`SMGC2D` — отдельный компонент с именем `"SMGC2D"`. Окно и контекст OpenGL он создаёт так же, как `SMGC`, но камеры, SSBO, ray-marching и буфера глубины у него нет. Сцена — это список фигур, каждая из которых сразу превращается в полигоны.

#### Координаты

Все позиции и размеры задаются в **пикселях framebuffer**: точка (0, 0) — левый верхний угол окна, x растёт вправо, y — вниз. Камера не двигается, а при растягивании окна фигуры не масштабируются: видимая область просто становится больше или меньше. Поворота у фигур нет: наклонные фигуры собираются из треугольников и отрезков.

#### Протокол задач 2D

Общие задачи из `taskDefinitions.h`, которые понимает `SMGC2D`:

| Задача | `taskIdx` | Что делает в 2D |
|--------|-----------|-----------------|
| `task_SmgcClearObjects` | `1` | Очищает буфер B. Служебной геометрии в 2D нет |
| `task_SmgcSwapObjects` | `0` | Меняет буферы A и B местами и загружает геометрию A в VBO/EBO |
| `task_SmgcSetOutline` | `3` | Включает или выключает оранжевый каркас. По умолчанию включён |
| `task_SmgcSubscribeKey` / `task_SmgcUnsubscribeKey` | `6` / `7` | Подписка на клавиши, как у `SMGC` |
| `task_SmgcKeyState` | `8` | Отправляется подписчикам каждый тик, как у `SMGC` |

Остальные задачи 3D (`PushObject`, `SetCamera`, `SetMaxDist`, `SetShadows`) `SMGC2D` молча игнорирует.

Задачи фигур из `taskDefinitions2D.h`. Каждая добавляет фигуру в буфер B, цвет у всех — RGBA `glm::vec4` с компонентами от 0 до 1:

| Задача | `taskIdx` | Данные | Фигура |
|--------|-----------|--------|--------|
| `task_SmgcDrawRect` | `11` | `glm::vec2 pos`, `glm::vec2 size`, `glm::vec4 color` | Прямоугольник, `pos` — левый верхний угол |
| `task_SmgcDrawTriangle` | `12` | `glm::vec2 a, b, c`, `glm::vec4 color` | Треугольник по трём вершинам, порядок обхода не важен |
| `task_SmgcDrawCircle` | `13` | `glm::vec2 center`, `float radius`, `glm::vec4 color` | Круг |
| `task_SmgcDrawEllipse` | `14` | `glm::vec2 center`, `glm::vec2 radii`, `glm::vec4 color` | Эллипс с полуосями `radii.x` и `radii.y`. Если одна из полуосей равна 0, ничего не рисуется |
| `task_SmgcDrawRoundedRect` | `15` | `glm::vec2 pos`, `glm::vec2 size`, `float cornerRadius`, `glm::vec4 color` | Скруглённый прямоугольник, `pos` — левый верхний угол. Радиус скругления ограничивается половиной меньшей стороны |
| `task_SmgcDrawRing` | `16` | `glm::vec2 center`, `float radius`, `float thickness`, `glm::vec4 color` | Кольцо: `radius` — внешний радиус, `thickness` — толщина внутрь. Толщина ограничивается радиусом, при `thickness = radius` получается круг |
| `task_SmgcDrawLine` | `17` | `glm::vec2 a, b`, `float thickness`, `glm::vec4 color` | Отрезок от `a` до `b` со скруглёнными концами. При `thickness = 0` рисуется сглаженная линия толщиной около 1 пикселя |
| `task_SmgcDrawText` | `18` | `std::string text`, `glm::vec2 pos`, `float size`, `glm::vec4 color`, `TextAlign align = TextAlign::Left` | Текст, см. [Текст](#текст) |
| `task_SmgcSetFont` | `19` | `std::string path` | Загружает другой шрифт TTF. Если файл не открылся или это не TTF, возвращает ошибку и оставляет прежний шрифт |

Размеры, радиусы и толщины должны быть конечными и не меньше 0. Иначе задача возвращает `-EINVAL`, пишет ошибку в лог, и фигура не добавляется.

Типичный кадр 2D-сцены:

```cpp
sendTask(std::make_unique<task_SmgcClearObjects>(), "SMGC2D");
sendTask(std::make_unique<task_SmgcDrawRect>(glm::vec2{50.0f, 50.0f}, glm::vec2{200.0f, 100.0f}, glm::vec4{0.2f, 0.4f, 0.8f, 1.0f}), "SMGC2D");
sendTask(std::make_unique<task_SmgcDrawCircle>(glm::vec2{400.0f, 400.0f}, 60.0f, glm::vec4{1.0f, 0.5f, 0.0f, 0.5f}), "SMGC2D");
sendTask(std::make_unique<task_SmgcSwapObjects>(), "SMGC2D");
```

Как и в 3D, буфер A показывается на экране, а буфер B собирается, поэтому сцену можно обновлять реже, чем раз в тик.

#### Как рисуются фигуры

- **Порядок.** Тест глубины и отсечение граней выключены, включено смешивание `GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA`. Фигуры рисуются в том порядке, в котором пришли задачи: последняя оказывается сверху, а полупрозрачная фигура смешивается со всем, что нарисовано под ней.
- **Полигоны.** Прямоугольник (2 треугольника) и треугольник рисуются как есть, сплошным цветом.
- **SDF-фигуры.** Круг, эллипс, скруглённый прямоугольник, кольцо и отрезок рисуются квадом, который охватывает фигуру с запасом в 1 пиксель. Фрагментный шейдер считает расстояние со знаком `d` от пикселя до края фигуры в пикселях и покрытие `clamp(0.5 - d, 0, 1)`: внутри фигуры оно равно 1, на краю плавно спадает до 0 — так получается сглаживание. Пиксели с нулевым покрытием отбрасываются (`discard`), у остальных покрытие умножается на альфа-канал цвета.
- **Отрезок** строится квадом вдоль направления `b − a`, расширенным на половину толщины и 1 пиксель во все стороны, поэтому наклонные линии не требуют поворота.
- **Текст** — квад на каждый видимый глиф, его форма берётся из SDF-атласа шрифта (см. [Текст](#текст)).
- **Каркас.** После заливки, если каркас включён, тот же набор треугольников рисуется в режиме `GL_LINE` оранжевым цветом. У SDF-фигур и глифов видны охватывающие квады и их диагонали, что удобно для отладки. Мелкий текст под каркасом читается плохо: его можно выключить задачей `task_SmgcSetOutline`.

Кадр рисуется в 1 проход заливки и 1 проход каркаса, экран перед этим очищается в чёрный.

#### Шейдеры 2D

`files/display2D.vert` переводит пиксели в NDC: `x = pos.x / iResolution.x · 2 − 1`, `y = 1 − pos.y / iResolution.y · 2`. Цвет, параметры и тип фигуры передаются во фрагментный шейдер без интерполяции (`flat`), локальные координаты `local` интерполируются.

`files/display2D.frag` выбирает SDF по типу фигуры:

| Тип (`SHAPE_*`) | SDF | Параметры |
|-----------------|-----|-----------|
| `SHAPE_POLYGON` (0) | — | Сплошной цвет без сглаживания |
| `SHAPE_CIRCLE` (1) | `length(p) − r` | `params.x` — радиус |
| `SHAPE_ELLIPSE` (2) | Приближённое расстояние до эллипса `k0 · (k0 − 1) / k1` | `params.xy` — полуоси |
| `SHAPE_ROUNDED_RECT` (3) | Расстояние до скруглённого бокса | `params.xy` — половина размера, `params.z` — радиус скругления |
| `SHAPE_RING` (4) | `abs(length(p) − r + t/2) − t/2` | `params.x` — внешний радиус, `params.y` — толщина |
| `SHAPE_LINE` (5) | Расстояние до отрезка минус половина толщины | `params.xy` — вектор `b − a`, `params.z` — половина толщины |
| `SHAPE_TEXT` (6) | `(TEXT_EDGE − texture(iFont, uv).r) · k` | `local` — координаты в атласе, `params.x` — `k`, перевод значения атласа в пиксели экрана |

Значения `SHAPE_*` должны совпадать с `enum class Shape2D` в `Shapes2D.h`.

Uniform-переменные, которые `SMGC2D` задаёт каждый кадр:

| Uniform | Тип | Значение |
|---------|-----|----------|
| `iResolution` | `vec2` | Размер framebuffer в пикселях |
| `iOutline` | `float` | `1` — оранжевый цвет (проход каркаса), `0` — заливка |
| `iFont` | `sampler2D` | Атлас шрифта, текстурный блок 0 (значение по умолчанию, отдельно не задаётся) |

Атрибуты вершин:

| location | Поле `Vertex2D` | Тип |
|----------|-----------------|-----|
| 0 | `pos` | `vec2` |
| 1 | `local` | `vec2` |
| 2 | `color` | `vec4` |
| 3 | `params` | `vec4` |
| 4 | `shape` | `int`, через `glVertexAttribIPointer` |

### Текст

Текст рисуют оба компонента одной и той же задачей:

```cpp
sendTask(std::make_unique<task_SmgcDrawText>("Привет, мир!\nВторая строка", glm::vec2{400.0f, 20.0f}, 32.0f, glm::vec4{1.0f}, TextAlign::Center), "SMGC2D");
```

| Параметр | Значение |
|----------|----------|
| `text` | Строка в UTF-8. `\n` переносит строку, `\r` пропускается |
| `pos` | Точка привязки в пикселях. `pos.y` — верх первой строки. `pos.x` — левый край, центр или правый край **каждой** строки, в зависимости от `align` |
| `size` | Высота шрифта в пикселях: расстояние от верха самых высоких букв до низа самых длинных выносных. Межстрочный интервал берётся из шрифта (`ascent − descent + lineGap`), у DejaVu Sans он равен `size`. Должен быть конечным и не меньше 0, иначе `-EINVAL` |
| `color` | Цвет RGBA, альфа-канал работает как у фигур |
| `align` | `TextAlign::Left` (по умолчанию), `TextAlign::Center` или `TextAlign::Right` |

**Символы.** В атлас при загрузке шрифта попадают диапазоны:

| Диапазон | Что входит |
|----------|------------|
| U+0020–U+007E | ASCII |
| U+00A0–U+00FF | Латиница-1: «», °, ±, ×, буквы с диакритикой |
| U+0400–U+045F | Кириллица, включая Ё/ё |
| U+2010–U+2027 | Дефисы и тире, кавычки „“ ‘’, •, … |
| U+2030–U+203A | ‰, ′, ″, ‹ › |
| U+20AC | € |
| U+2116 | № |

Символы вне этих диапазонов, символы, которых нет в шрифте, и неверные последовательности UTF-8 заменяются на `?`. Между парами букв применяется кернинг шрифта.

**Как это работает.** `Font::Load` читает файл TTF и для каждого символа строит через stb_truetype SDF-битмап размером 48 пикселей с полем в 8 пикселей. Все битмапы укладываются в одну текстуру `GL_R8` шириной 1024 пикселя. Значение 128 в атласе — граница глифа, больше — внутри. `Text2D` раскладывает строку и добавляет на каждый видимый глиф квад с координатами атласа в `local`. Фрагментный шейдер переводит значение атласа в расстояние до края в пикселях экрана и считает покрытие так же, как у остальных SDF-фигур, поэтому текст сглажен на любом размере. Пробелы квадов не получают, а только сдвигают перо.

**Шрифт.** При инициализации загружается `files/DejaVuSans.ttf`, без него компонент не запустится. Задача `task_SmgcSetFont` с путём к другому файлу TTF перестраивает атлас. Если загрузка не удалась, задача возвращает `-ENOENT` (файл не открылся) или `-EINVAL` (не TTF), а прежний шрифт остаётся. Текст, уже собранный в буферах A и B, хранит координаты старого атласа, поэтому шрифт лучше менять до `Clear`, а до следующего `Swap` текст на экране может выглядеть неверно.

### Текст поверх 3D-сцены

`SMGC` принимает `task_SmgcDrawText` и `task_SmgcSetFont` и рисует текст как HUD: в пикселях окна, поверх 3D-сцены, без теста глубины. Для этого у него есть свой `Layer2D` (`overlay`) с 2D-шейдерами и шрифтом:

- `task_SmgcClearObjects` очищает и текст, `task_SmgcSwapObjects` показывает его вместе с новой сценой. Поэтому текст отправляется между `Clear` и `Swap`, как объекты;
- текст рисуется в конце `draw()`, после каркаса. Каркас текста включается и выключается той же задачей `task_SmgcSetOutline`;
- остальные 2D-фигуры `SMGC` пока не принимает.

### VBO, EBO и ObjectsBuffer

`include/smgc/VBO.h`, `include/smgc/EBO.h`, `include/smgc/ObjectsBuffer.h` и одноимённые `.cpp` в `src/smgc/`.

Три обёртки над буферами OpenGL с одинаковым поведением `Upload`: если размер данных не изменился, буфер перезаписывается через `glBufferSubData`, иначе пересоздаётся через `glBufferData` с `GL_DYNAMIC_DRAW`. Текущий размер хранится в `capacityBytes`.

| Класс | Буфер | Данные | Методы |
|-------|-------|--------|--------|
| `VBO` | `GL_ARRAY_BUFFER` | `std::vector<Vertex>` или указатель и размер в байтах (`Upload(const void* data, size_t bytes)`) для вершин любого формата | `Upload`, `Bind`, `Unbind`, `Delete` |
| `EBO` | `GL_ELEMENT_ARRAY_BUFFER` | `std::vector<GLuint>` | `Upload`, `Bind`, `Unbind`, `Delete` |
| `ObjectsBuffer` | `GL_SHADER_STORAGE_BUFFER` | `std::vector<GpuObject>` | `Upload`, `Bind(int bind)` — привязка к точке `binding`, `Delete` |

`Upload` у EBO привязывает буфер к `GL_ELEMENT_ARRAY_BUFFER` и отвязывает его в конце. Если в этот момент привязан VAO, EBO отвяжется и от него, поэтому EBO загружается только без привязанного VAO.

Структура вершины:

| Поле | Тип | Описание |
|------|-----|----------|
| `pos` | `glm::vec3` | Позиция |
| `attached` | `float` | `0` — вершина в мировых координатах, `1` — в системе камеры (следует за позицией и поворотом камеры) |
| `objectIdx` | `GLint` | Номер объекта в SSBO; `-1` — пол (значение по умолчанию), `-2` — `AntiCube` |
| `polygonal` | `float` | `0` — ray-marching (по умолчанию), `1` — полигональное затенение |

Структура `VertexAttributes` (там же, в `VBO.h`) — атрибуты, которые производитель передаёт в `task_SmgcPushObject`:

| Поле | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `polygonal` | `bool` | `false` | Рисовать объект полигонами |
| `attached` | `bool` | `false` | Объект задан в системе камеры |

| `void Text2D(vertices, indices, const Font& font, const std::string& text, const glm::vec2& pos, float size, const glm::vec4& color, TextAlign align)` | Квад на каждый видимый глиф, `Shape2D::Text`. Декодирует UTF-8, переносит строки по `\n`, применяет кернинг и выравнивание. Ничего не добавляет, если шрифт не загружен |

Структура вершины `Vertex2D`:

| Поле | Тип | Описание |
|------|-----|----------|
| `pos` | `glm::vec2` | Позиция в пикселях |
| `local` | `glm::vec2` | Смещение от опорной точки фигуры в пикселях: от центра у круга, эллипса, кольца и скруглённого прямоугольника, от `a` у отрезка. У текста — координаты в атласе шрифта |
| `color` | `glm::vec4` | Цвет RGBA |
| `params` | `glm::vec4` | Параметры SDF, см. таблицу в [Шейдеры 2D](#шейдеры-2d) |
| `shape` | `GLint` | Тип фигуры, значение `Shape2D` |

`enum class Shape2D : GLint`: `Polygon = 0`, `Circle = 1`, `Ellipse = 2`, `RoundedRect = 3`, `Ring = 4`, `Line = 5`, `Text = 6`.

### Функции paletts.h

`include/smgc/paletts.h`, `src/smgc/paletts.cpp`

| Функция | Описание |
|---------|----------|
| `glm::vec3 PaletteCosinka(float t)` | Косинусная палитра: `t` ограничивается отрезком [0, 1], результат — цвет RGB в [0, 1]. Основная волна, вторая волна для «характера» и яркий горб в середине. |

## Соглашения

- **Коды возврата.** Как в smpb: `0` — успех, ошибки — отрицательный `errno`: `-ENODEV` (не удалось создать окно, загрузить OpenGL или нет буфера), `-EINVAL` (ошибка шейдера, недопустимое значение в задаче).
- **Логи.** Информационные сообщения пишутся в `std::clog`, ошибки в `std::cerr`, сообщения компонента начинаются с `getPrefix()`. Комментарии и логи пишутся на русском или английском, в зависимости от окружающего кода.
- **Заголовки** подключаются с префиксом: `<smgc/X.h>`, `<smpb/X.h>`.
- **Новые файлы** `.cpp` и `.h` добавляются в список исходников `CMakeLists.txt` вручную, поиска по маске нет.
- **Новая задача** получает уникальный `taskIdx` (общий для `taskDefinitions.h` и `taskDefinitions2D.h`), функцию `taskIs_*` и ветку в `processTask` нужного компонента: `SMGC` или `SMGC2D`.
- **Новый тип объекта** добавляется в 3 места: SDF в `default.frag` (`map`), прокси-меш в `GenerateObject` и радиус в `ObjectBoundingRadius`. Прокси обязан охватывать SDF.
- **Новая 2D-фигура** добавляется в 5 мест: значение в `Shape2D` и такой же `SHAPE_*` с SDF в `display2D.frag`, генератор в `Shapes2D`, задача в `taskDefinitions2D` и метод `draw*` в `SMGC2D`. Квад SDF-фигуры обязан охватывать её с запасом в 1 пиксель для сглаживания.
- **Текст.** Граница глифа в атласе — значение 128: `kOnEdge` в `Font.cpp` и `TEXT_EDGE` в `display2D.frag` должны совпадать. Новые символы добавляются диапазоном в `kRanges` в `Font.cpp`.
- **`GpuObject`** в C++ и `Object` в GLSL должны совпадать, размер проверяется `static_assert`.
- **Подписчик на клавиши** обязан отписаться от всех клавиш в своём `death()`.

## Пример: свой компонент-сцена

### 3D

```cpp
#include <smpb/Core.h>
#include <smpb/Config.h>
#include <smgc/display3D.h>

#include <cmath>

class Orbit : public BaseComponent {
public:
    Orbit() : BaseComponent("Orbit") {}

    int tick(long long tickCounter) override {
        float time = float(tickCounter) / float(Core_getTPS());
        glm::vec3 col = PaletteCosinka(std::fmod(time * 0.1f, 1.0f));

        sendTask(std::make_unique<task_SmgcClearObjects>(), "SMGC");

        // Губка Менгера, вращается вокруг оси Y
        sendTask(std::make_unique<task_SmgcPushObject>(std::make_unique<Object>(
            glm::vec4{-2.0f, 0.0f, 0.0f, 5.0f},
            glm::vec4{1.0f, 0.0f, 0.0f, 0.0f},
            glm::vec4{0.9f, 0.9f, 0.9f, 1.0f},
            glm::vec4{0.0f, time, 0.0f, 0.0f}
        )), "SMGC");

        // Шар, летает вокруг губки
        sendTask(std::make_unique<task_SmgcPushObject>(std::make_unique<Object>(
            glm::vec4{1.0f, std::cos(time) * 2.5f, 0.0f, 5.0f + std::sin(time) * 2.5f},
            glm::vec4{0.5f, 0.0f, 0.0f, 0.0f},
            glm::vec4{col, 1.0f},
            glm::vec4{0.0f}
        )), "SMGC");

        sendTask(std::make_unique<task_SmgcSwapObjects>(), "SMGC");
        return 0;
    }
};

int main(int argc, char *argv[]) {
    Core core;
    core.appendComponent(std::make_unique<Config>(argc, argv));
    core.appendComponent(std::make_unique<SMGC>());
    core.appendComponent(std::make_unique<Orbit>());

    core.init();
    return core.cycle();
}
```

### 2D

Часы с секундной стрелкой в центре окна 800×800 и счётчиком секунд под ними, без каркаса:

```cpp
#include <smpb/Core.h>
#include <smpb/Config.h>
#include <smgc/display2D.h>

#include <cmath>
#include <format>

class Clock : public BaseComponent {
public:
    Clock() : BaseComponent("Clock") {}

    int init() override {
        return sendTask(std::make_unique<task_SmgcSetOutline>(false), "SMGC2D");
    }

    int tick(long long tickCounter) override {
        float time = float(tickCounter) / float(Core_getTPS());
        glm::vec2 center{400.0f, 400.0f};
        glm::vec2 hand{std::sin(time), -std::cos(time)};

        sendTask(std::make_unique<task_SmgcClearObjects>(), "SMGC2D");
        sendTask(std::make_unique<task_SmgcDrawCircle>(center, 200.0f, glm::vec4{0.15f, 0.15f, 0.2f, 1.0f}), "SMGC2D");
        sendTask(std::make_unique<task_SmgcDrawRing>(center, 200.0f, 8.0f, glm::vec4{1.0f}), "SMGC2D");
        sendTask(std::make_unique<task_SmgcDrawLine>(center, center + hand * 170.0f, 6.0f, glm::vec4{PaletteCosinka(0.3f), 1.0f}), "SMGC2D");
        sendTask(std::make_unique<task_SmgcDrawCircle>(center, 12.0f, glm::vec4{1.0f}), "SMGC2D");
        sendTask(std::make_unique<task_SmgcDrawText>(std::format("{} с", tickCounter / Core_getTPS()), glm::vec2{400.0f, 620.0f}, 40.0f, glm::vec4{1.0f}, TextAlign::Center), "SMGC2D");
        sendTask(std::make_unique<task_SmgcSwapObjects>(), "SMGC2D");
        return 0;
    }
};

int main(int argc, char *argv[]) {
    Core core;
    core.appendComponent(std::make_unique<Config>(argc, argv));
    core.appendComponent(std::make_unique<SMGC2D>());
    core.appendComponent(std::make_unique<Clock>());

    core.init();
    return core.cycle();
}
```

Стрелка задаётся двумя точками, поэтому для неё не нужен поворот: при y, направленном вниз, вектор `(sin t, −cos t)` в момент 0 смотрит вверх и вращается по часовой стрелке.
